## Delivery shape and compatibility

The Astro build produces pre-rendered HTML in `dist/`. Root `wrangler.jsonc` publishes those static assets together with the Rust/Wasm Worker from `worker/`. Static content should be served as assets when it exists; only API paths need Worker execution. This preserves crawlable HTML, existing URLs, the site's theme/layout and the feed/sitemap/`llms.txt` endpoints without introducing a client-side-rendering dependency. Review changes to `wrangler.jsonc`, route ownership and asset handling together: a successful Wasm compilation alone does not prove that static routes remain reachable.

The canonical host is `atelier.moesegfault.dev`. A Cloudflare [Workers Route](https://developers.cloudflare.com/workers/configuration/routing/routes/) at `atelier.moesegfault.dev/*` is attached. The existing CNAME still targets `kleedaisuki.github.io`, but its `proxied` flag is now **true** after the successful manual cutover; a Route receives traffic only when that flag is true. The cutover did **not** delete or replace the CNAME. Setting the flag back to `false` bypasses Cloudflare and restores direct GitHub Pages traffic after DNS caches refresh. This deliberately differs from a Workers Custom Domain, which conflicts with an existing CNAME. See [Cloudflare proxy status](https://developers.cloudflare.com/dns/proxy-status/). The repository `CNAME` file remains necessary for GitHub Pages rollback and does not configure Workers.

## One-time Cloudflare and GitHub setup

1. `moesegfault.dev` is an active Cloudflare DNS zone. D1 `atelier-subscriptions` and migration `worker/migrations/0001_init.sql` are provisioned/applied remotely, and root `wrangler.jsonc` declares the `DB`, `EMAIL`, and `SUBSCRIBE_LIMIT` bindings. For a new account or recovery, provision these before deploy. **Sending to arbitrary opt-in subscribers requires Workers Paid**, not the Free plan; verify the actual account plan and quota before live subscriber mail ([Email Service pricing](https://developers.cloudflare.com/email-service/platform/pricing/)).
2. Create a narrowly scoped Cloudflare API token with Workers deployment, **D1 Edit**, and zone-scoped **DNS Read/Write** permissions, limited to the target account and zone. Save the token and account ID as GitHub Actions repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. The workflow intentionally fails rather than silently skips production deployment when either is missing. See [Cloudflare's GitHub Actions guide](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/), [D1 migration commands](https://developers.cloudflare.com/d1/wrangler-commands/), and [DNS API permissions](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/edit/).
3. `ATELIER_NOTIFY_TOKEN` is already configured as both a Worker runtime secret and a GitHub Actions secret. They must hold the **same value**; rotate them together. For recovery, use `pnpm exec wrangler secret put ATELIER_NOTIFY_TOKEN` (or the dashboard), then update GitHub. This protects `POST /api/admin/notify` and `GET /api/admin/status`; it is not an email-provider API key. The native `send_email` binding supplies Cloudflare Email Service without a provider credential. Do **not** put the admin token under `vars`, commit `.dev.vars`, or print it. `wrangler secret put` creates/deploys a Worker version; coordinate rotation with release. See [Workers secrets](https://developers.cloudflare.com/workers/configuration/secrets/).
4. The Email Sending domain is enabled and one notification to an owned Cloudflare-verified mailbox reached D1 `sent` after the provider binding returned success. Before broader subscriber dispatch, verify current SPF/DKIM/DMARC/bounce DNS status, `atelier@moesegfault.dev` sender eligibility, account plan/quota, arbitrary recipient eligibility, actual inbox placement, and delivered one-click-unsubscribe headers. A successful binding call for a verified mailbox does **not** establish arbitrary-recipient deliverability. See [Email Sending setup](https://developers.cloudflare.com/email-service/get-started/send-emails/) and [send binding restrictions](https://developers.cloudflare.com/email-service/configuration/send-bindings/). The notification-versus-bulk policy nuance is recorded in [the mail architecture](cloudflare-worker-mail-architecture.md#email-provider-fit-decision-and-remaining-evidence).
5. If a GitHub Environment is used for approval or environment-scoped secrets, adapt the workflow to use a separate deploy job gated on `main` and that environment; the current single-job workflow reads **repository** secrets only at the deploy step.

## CI and release

`.github/workflows/deploy.yml` runs on pull requests, pushes to `main`, and manual dispatch. It installs pinned pnpm/Node and the Rust Wasm target, checks Rust formatting and tests, runs Astro/type/unit/lint/format/build/SEO checks, validates D1 migrations locally, runs browser tests, then performs `wrangler deploy --dry-run` to exercise the combined bundle. Only a successful run on `main` applies D1 migrations remotely and deploys via Cloudflare's official [`wrangler-action@v4`](https://github.com/cloudflare/wrangler-action). Review schema changes for backward compatibility: migrations run **before** the new Worker, so the old Worker must tolerate the new schema during rollout or rollback. Diagnostic browser artifacts upload even when tests fail. The workflow grants only `contents: read`; it does not use GitHub Pages permissions or upload a Pages artifact.

On a **push to `main` only**, after Worker deployment succeeds, `scripts/dispatch-notifications.mjs` compares the push's before/after commits and submits changed `notifications/*.json` manifests **or manifests whose sibling HTML changed** to `POST /api/admin/notify`. GitHub repository variable `ATELIER_WORKER_URL` is the live HTTPS Worker origin (the `workers.dev` origin works independently of DNS proxy state), and repository secret `ATELIER_NOTIFY_TOKEN` matches the Worker secret. No changed manifest/HTML means no token or URL is needed. Manual dispatch never sends notifications. The manifest format is `{ "id": "stable-campaign-id", "subject": "...", "html_file": "sibling.html", "send": false }`. Its HTML is an editable sibling file and must include `{{unsubscribe_url}}` for each recipient's opt-out link. `send: false` saves a draft; change to `true` only after reviewing the exact message and recipient semantics. The Worker enforces idempotency by `id` and rejects changed content after a campaign is queued or sent; to send a new update, use a new `id`. See `notifications/atelier-update.json` for a draft example.

For a local preflight (the successful GitHub Actions run remains the release gate):

```sh
pnpm install --frozen-lockfile
cargo install worker-build --version '^0.8' --locked
pnpm run check && pnpm test && pnpm run build
pnpm run verify:seo
cargo test --manifest-path worker/Cargo.toml --locked
node --test tests/notification-dispatch.test.mjs
pnpm exec wrangler d1 migrations apply DB --local --persist-to .cache/wrangler
pnpm exec wrangler deploy --dry-run
```

`wrangler deploy --dry-run` checks packaging but cannot verify account permissions, remote bindings, DNS, Email Service onboarding, or live delivery. ## Cutover smoke tests and rollback

For future activation or re-activation, inspect the deploy Action log and verify the `workers.dev` preview first. Run **Actions → Manual Cloudflare DNS cutover → activate** from `main` only when preview is healthy. The workflow checks pre-rendered `/zh/` and Rust `/api/health`, reads the exact CNAME, requires exactly one record targeting `kleedaisuki.github.io`, PATCHes only `proxied: true`, then waits for canonical page and Worker health to converge. It fails closed if permissions or records are ambiguous. `CLOUDFLARE_API_TOKEN` needs **DNS Read and DNS Write** for this zone. `ATELIER_WORKER_URL` must be `https://atelier-moesegfault.moesegfault.workers.dev/` for preview verification. [Action 36133244601](https://github.com/kleedaisuki/kleedaisuki.github.io/actions/runs/36133244601) exercised this path: the DNS flag was patched at 12:08:45 UTC and canonical checks converged at 12:13:46 UTC. This is a sampled successful cutover, **not** proof of worldwide propagation. See [DNS list](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/list/) and [DNS PATCH](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/edit/).

After activation, check both localized homepages and representative blog/articraft pages with `curl` or a browser, then verify `/rss.xml`, `/llms.txt`, sitemap URLs, original downloadable assets, and a nonexistent URL's 404 behavior. Confirm HTML contains expected title/canonical/hreflang and body content without executing JavaScript. Test the subscription flow with an owned mailbox, including consent/unsubscribe semantics and an actual rendered HTML message; never mail an unconsenting address to smoke-test production.

If cutover is defective, run **Actions → Manual Cloudflare DNS cutover → rollback** from `main`. It PATCHes only `proxied: false` on that same validated CNAME, verifies the canonical page still works, and requires the Worker health endpoint to disappear. DNS cache propagation can take minutes; a failed post-switch health check does not silently issue a second DNS change, so inspect the current DNS flag and rerun rollback if necessary. For a defect in a later Worker release after cutover, Cloudflare's [deployment rollback](https://developers.cloudflare.com/workers/configuration/versions-and-deployments/rollbacks/) or redeployment of a known-good Git revision may be more appropriate. Static asset and Worker versions should be rolled back together, not independently.
